# Local Report Studio v1.3.0 契约

状态：规范性基线  
应用版本：`1.3.0`  
工程格式：`ReportDocument 1.3`

本文定义 v1.3.0 必须保持的行为。文中的“必须”表示破坏后需要提升相应版本并更新迁移、文档和验收；“应该”表示允许有明确理由的实现差异，但不得默默改变用户数据或输出含义。

## 1. 版本契约

1. `VERSION`、`package.json.version` 和发布清单 `applicationVersion` 必须均为 `1.3.0`。
2. `ReportDocument.version`、模板写入版本和发布清单 `documentSchemaVersion` 必须均为 `1.3`。
3. 应用语义版本与文档 schema 独立演进。修复 UI 而不改变持久化结构时可以只提升应用补丁版本；改变 JSON 结构或字段语义时必须提升 schema。
4. v1.3.0 必须接受 `ReportDocument 1.0`、`1.1`、`1.2` 和 `1.3`，并把运行态归一为 `1.3`。
5. v1.3.0 不承诺向 1.0-1.2 降级导出。

## 2. 单一事实源契约

1. 报告结构的唯一持久化事实源必须是 `ReportDocument`。
2. 页面、元素、主题、页面设置和图片资产元数据必须存在于 `ReportDocument`。
3. 图片二进制不得存入运行态 `ReportDocument`、撤销快照或普通自动保存 JSON；必须通过 `assetId` 引用 IndexedDB Blob。
4. `.report.json` 顶层 `assetData` 只允许作为可移植归档封装。导入后必须把数据写入 IndexedDB，并从运行态文档主体移除。
5. 当前选择、框选矩形、吸附参考线、裁切手柄、缩放比例、面板开关、检查弹窗和其他编辑装饰不得进入工程 JSON。
6. 编辑态与打印态必须复用相同的页面、元素、文本、图片和图表渲染组件；打印态只能关闭编辑装饰并改变长度投影。

## 3. 坐标与页面契约

1. `ReportElement.x/y/w/h` 的单位必须始终为 mm。
2. A4 纵向必须为 `210 x 297 mm`，横向必须为 `297 x 210 mm`。
3. 编辑投影必须由绝对文档坐标计算：

   ```text
   screenPx = documentMm x BASE_PX_PER_MM x zoomPercent
   ```

4. 打印投影必须直接使用 CSS mm，不得依赖当前编辑缩放。
5. 改变缩放、打开面板或滚动画布不得改写任何元素几何。
6. 元素移动和缩放必须受页面边界约束。锁定或隐藏元素不得被几何命令修改。
7. 持久化几何默认保留到 0.1 mm；视觉投影允许产生设备像素级小数。

## 4. 文档模型契约

### 4.1 顶层结构

`ReportDocument 1.3` 必须包含：

```ts
interface ReportDocument {
  version: "1.3";
  meta: ReportMeta;
  theme: ThemeTokens;
  pageSetup: PageSetup;
  usedFontSlots: Array<"display" | "body" | "numeric">;
  assets: ReportAsset[];
  pages: ReportPage[];
  updatedAt: string;
}
```

### 4.2 页面类型

`ReportPage.master` 只允许：

```text
cover | section | standard | data | blank | backcover
```

页面背景必须通过 `masterProps.imageAssetId` 引用资产，焦点坐标必须以 0-100 的百分比表达。`masterProps.imageStyle` 只能存图片风格枚举、主题颜色 token 和 0-1 强度，不得存任意 CSS。

### 4.3 元素类型

`ReportElement.type` 只允许：

```text
title | text | kpi | line-chart | bar-chart | combo-chart | donut-chart
table | quote | source | image | divider
```

所有可见制度对象必须是普通 `ReportElement`。`role` 只允许：

```text
header-left | header-right | header-rule
footer-left | footer-page-number | footer-rule
backcover-organization | backcover-disclaimer
backcover-contact | backcover-confidentiality
```

这些角色元素必须和业务元素共用选择、图层、几何、对齐、锁定、显隐、历史和打印系统。渲染器不得再生成不可编辑的重复页眉、页脚、页码或制度文字。

### 4.4 文本与样式

1. 持久化文本不得包含 HTML 字符串。
2. `runs` 只允许 `text` 与 `bold`、`accentRed`、`accentGreen` marks。
3. `content` 是 runs 的纯文本镜像，用于兼容和检索；归一化后必须与 runs 拼接结果一致。
4. 字体槽只允许 `display`、`body`、`numeric`。
5. 元素字号只允许 `8/10/12/14/28 pt`；导入其他字号必须吸附到最近档位。
6. 元素颜色、背景色和边框色只允许 `ThemeColorToken`，不得把任意 hex 写入元素样式。主题定义本身可以保存明确色值。
7. 用户可选择的行高只允许 `1.2/1.35/1.5`；模板内部已经固化的排版值属于 v1.3.0 模板预设，不得通过自由输入暴露给用户。
8. 字体缺失时不得静默宣称版式一致，必须报告字体替换风险。

## 5. 历史与事务契约

1. 普通 `commit()` 必须把修改前的结构快照放入历史并清空重做栈。
2. 历史最多保留 80 个过去状态；图片二进制不得进入快照。
3. 拖动、缩放和裁切在指针移动期间只产生预览，指针释放时至多形成一条历史。
4. 属性面板中同一元素同一字段的连续输入必须按 merge key 合并，静默 500 ms 后结束事务。
5. 一次页内文本编辑会话提交时至多形成一条全局历史；`Esc` 必须恢复进入会话前的文档。
6. 页面背景与自由图片互转、设为背景、添加页面、复制页面、删除页面和组合图系列配置必须可撤销。
7. 撤销与重做只改变 `ReportDocument`，不得改变 IndexedDB 中的图片体。

## 6. 选择、对齐与吸附契约

### 6.1 选择

1. 单击必须选择一个可见、未被上层命中区域遮挡的元素。
2. `Shift/Ctrl/Command` 单击必须增减选择。
3. 空白画布框选必须以元素包围盒命中当前页元素。
4. 多选几何操作必须使用整个可移动选区的包围盒，不得隐式选择“主元素”作为几何基准。

### 6.2 显式对齐

1. 单选左/中/右、上/中/下对齐必须使用完整页面边界。
2. 多选相同命令必须使用当前选区包围盒。
3. 水平或垂直分布必须至少有三个未锁定、可见元素。
4. 分布必须保持首尾边界，并把剩余间距均分。
5. 每个命令必须是一个可撤销事务。

### 6.3 拖动与缩放吸附

1. 移动包围盒必须比较左/中/右与上/中/下特征线。
2. 候选目标必须包括页面边缘、页面中心、页边距、网格以及其他可见元素相应特征线。
3. 阈值必须按屏幕空间计算：`thresholdMm = 8px / pxPerMm`。
4. 参考线坐标和最终持久化坐标必须来自同一个命中目标。
5. 多选拖动必须把同一 delta 应用于全部可移动元素。
6. 按住 `Alt` 必须临时跳过吸附。

## 7. 页内文本编辑契约

1. 页面直接编辑必须使用原生 `input` 或 `textarea`，不得使用 `contenteditable`、`execCommand` 或把 HTML 当作编辑结果。
2. 编辑控件必须与被编辑字段几何重合，输入内容和光标在编辑期间必须可见。
3. 单行控件必须有非零宽度，并随内容增长但不得突破元素可用宽度。
4. 中文 IME 的 `compositionstart` 到 `compositionend` 期间不得提交、切换字段或触发编辑器快捷键。
5. 粘贴必须剥离格式并只写纯文本。
6. `Esc` 取消，`Tab` 提交并移动到下一个字段；单行 Enter 或 `Ctrl/Command + Enter` 必须提交。
7. 图表 SVG 内文字和数据不属于画布直接编辑范围，必须通过属性面板修改。

## 8. 缩放契约

1. 编辑缩放范围必须是 50%-200%，步进 5%。
2. `Ctrl/Command + 滚轮` 必须阻止浏览器页面缩放，并修改编辑器画布缩放。
3. 缩放前必须记录鼠标下方的页面 mm 点，布局后应该补偿滚动位置，使该点保持在光标附近。
4. 缩放必须从绝对 mm 坐标与当前 zoom 重新投影，不得连续缩放已缩放后的元素数据。
5. 浏览器滚动边界、居中状态切换和设备像素取整允许产生小于约 1 px 的瞬时视口偏差；不得把这种偏差写回文档几何。
6. 重复缩放不得造成报告元素坐标精度逐步丢失。视口位置不是持久化报告契约。

## 9. 页面背景与图片契约

1. 六种页面类型都必须能设置页面背景。
2. `section` 背景槽必须为顶部 70 mm；其余页面类型必须为整页。
3. 背景必须使用 cover 取景和焦点百分比，不得因为替换横图或竖图而改变文本元素几何。
4. 背景不得进入普通图层、吸附候选或多选包围盒；它只能通过页面检查器修改。
5. 内容图片必须是 `type: "image"` 的普通元素，参与图层、吸附和几何编辑。
6. 背景转自由图片以及自由图片设为背景必须复用同一资产，不得复制图片二进制。
7. 图片裁切必须是非破坏的，只修改 `{sx, sy, sw, sh}`，不得覆盖原始 Blob。
8. 图片导入必须通过 Canvas 重绘校正方向并移除 EXIF/GPS；默认优化不得让最长边超过 4096 px。
9. 相同像素内容应该通过 SHA-256 复用资产记录。

## 10. 图表与表格契约

1. 图表必须使用 ECharts SVG renderer，不能把整个报告页面栅格化。
2. TSV 图表数据必须把首列解释为类目，其余列解释为系列。
3. `combo-chart` 的每个系列必须可独立设置 `kind: bar|line`、`axis: left|right` 和 `unit`。
4. 组合图粘贴新 TSV 时应该按系列索引保留已有 kind、axis 和 unit；新增系列使用最后一列为右轴折线、其他列为左轴柱的默认值。
5. 表格 TSV 第一行必须作为表头，其余行作为正文。
6. 打印前所有图表必须关闭动画、同步重设 option 并 resize，完成后才能调用 `window.print()`。
7. 页面存在图表而缺少显式 `source` 元素时必须提示；工具不得自动捏造来源行。

## 11. 存储与工程包契约

1. 文档结构自动保存键固定为 `local-report-studio:document:v1`。
2. 图片 Blob 数据库固定为 `local-report-studio-assets-v1`，对象仓库为 `blobs`。
3. 自动保存或 IndexedDB 写入失败必须显示持续错误，不得静默丢失。
4. 默认工程包必须为 `.report.zip`，根目录包含 `document.json`，图片位于 `assets/`。
5. 单文件归档可以使用 `.report.json` 与顶层 base64 `assetData`，界面必须说明体积开销。
6. 导入工程时必须验证顶层结构和支持的 schema 版本，重复或缺失 ID 必须归一化。
7. 工程图片总量超过 50 MB 必须提示；该值是预算告警，不是硬性导入上限。
8. 未使用资产只能提示或经用户命令清理，不得自动删除。

## 12. 打印契约

1. 打印态必须复用报告渲染组件，不得维护第二套页面模板。
2. 纵向和横向页面必须分别使用命名 `@page`，并允许在同一报告中混排。
3. DOM 文字必须保持可搜索；ECharts 图表应保持 SVG 矢量内容。
4. 图片打印副本只用于本次打印，不得替换原工程资产。
5. 打印图片档位只允许 96、150 或 300 DPI。
6. 打印前检查必须覆盖页面越界、来源、字号、表格溢出估计、隐藏图表标签、字体、背景图、压图对比、图片清晰度、资产体积和未使用资产。
7. 检查提示可以由用户确认后继续打印，但不得被工具静默修复为虚构内容。
8. 浏览器打印设置仍由用户控制；推荐 100% 比例、无页边距并启用背景图形。

## 13. 离线与隐私契约

1. 生产运行时代码不得引用 HTTP/HTTPS 资源。
2. 构建门禁必须扫描 HTML 资源属性、CSS `url()` 和 `src/` 源码字符串中的 HTTP/HTTPS URL。
3. 应用不得包含上传接口、账户、遥测、广告或远程字体。
4. 研究文档可以保留来源链接，但这些链接不得进入运行时请求路径。
5. 清除浏览器站点数据会删除自动保存和 IndexedDB 资产；应用文档必须明确要求重要工程导出归档。

## 14. 错误处理契约

以下情况必须给出可见错误或警告：

- localStorage 配额或写入失败。
- IndexedDB 不可用或图片写入失败。
- 工程文件结构无效或 schema 不支持。
- 工程引用的图片 Blob 缺失。
- 字体替换风险。
- 图片低于 150 DPI。
- 图片资产超过 50 MB 预算。
- 打印检查发现结构或质量风险。

错误消息必须给出恢复方向，例如立即导出工程、重新选择图片或返回编辑。

## 15. 固化与变更管理契约

v1.3.0 的交付物由以下文件共同定义：

- `VERSION`
- `package.json`
- `release/v1.3.0.json`
- `docs/feature-baseline-v1.3.0.md`
- `docs/contracts-v1.3.0.md`
- `dist/index.html`
- `artifacts/visual-qa/`

任何代码变更必须至少执行：

```bash
npm run verify:release
```

以下变更不得继续沿用 v1.3.0 发布清单：

- `dist/index.html` SHA-256 改变。
- 持久化 schema、字段单位或字段语义改变。
- 单选/多选对齐基准改变。
- 文本编辑从原生控件改为 HTML 编辑。
- 页面背景、制度元素、资产或打印事实源边界改变。
- 离线与隐私边界改变。

需要继续开发时，应提升应用版本并生成新的发布清单。schema 是否提升由持久化兼容性决定，不能仅凭 UI 改动机械提升。
