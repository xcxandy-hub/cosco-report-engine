# Local Report Studio v1.6.0 特性基线

状态：`release-candidate`  
应用版本：`1.6.0`  
工程格式：`ReportDocument 1.5`  
固化日期：`2026-08-15`

## 1. 本版目标

v1.6.0 把 v1.5.0 的“报告包生成作者基线”与通用编辑器的“人工微调”真正接通。用户可以在特化工具中录入真实数据、进入同一渲染器精修版式，再让后续数据重编译继续保留视觉修改，同时不允许视觉覆盖篡改绑定事实。

## 2. 新增能力

| 领域 | v1.6.0 基线 |
| --- | --- |
| 文档 | `ReportDocument 1.5`；1.0-1.5 导入，统一写出 1.5 |
| 视觉覆盖 | 作者基线与 `VisualOverrideSet` 分层；按稳定 page/element ID 保存几何、样式、裁切、图层和标签精修 |
| 事实保护 | `contentTemplate/chartBinding/tableBinding` 与制度元素受保护；侧栏只读，覆盖生成与读取时双重剥离 content/runs/chart/table；报告 meta 不进入覆盖 |
| 精修运行时 | 特化生成器可进入嵌入式通用编辑器；完成后保存覆盖，数据变化后自动重放 |
| 图表标签 | 系列/类目稳定 ID；auto/all/sparse/key/off；单点毫米拖动；portrait/landscape 偏移独立 |
| 图片 | 内容图和封面/章节/尾页母版图均可双击直接裁切；滚轮缩放、拖动取景、非破坏像素 crop |
| 重置 | “恢复示例”只重置数据；“恢复布局”只重置视觉精修 |
| 升级提示 | package version 变化按稳定 ID重放；目标消失时显示 orphan override，不按序号错配 |
| 资产安全 | 工程和报告包均对 PNG/JPEG/WebP 执行规范 base64、MIME 与文件签名校验；旧 IndexedDB 记录读取时重校验并按报告包隔离；转换零 fetch |
| 页面 | 继续支持逐页纵横混排；已有内容时拒绝直接换向；内核不设置固定最大页数 |
| 测试 | 新增 `test:overrides` 与 `test:assets`，并进入完整发布门禁 |

## 3. 用户可见工作流

1. 智能体根据脱敏稿制作报告包，内核生成作者布局。
2. 用户在本地特化工具录入真实数据，数据变化触发安全重编译。
3. 用户进入“布局精修”调整位置、尺寸、样式、图片裁切和图表标签。
4. 精修保存为独立覆盖；再次改数据时先重编译事实，再重放视觉覆盖。
5. 绑定图表的数据只能从本地数据面板修改；布局精修只允许查看其事实并调整视觉表达。
6. 用户可分别恢复脱敏示例或作者布局，两种操作互不清除对方状态。

## 4. 明确边界

- 当前覆盖迁移依靠稳定 ID，并报告找不到目标的孤儿项；尚无语义指纹或三方冲突合并。
- 横竖版共享同一个页面模型，但图表标签偏移分别存放；已有内容的整页方向切换不会自动重排。
- `finance-brief` 仍是首个完整参考实现，当前基线编译为十页。发布检查从本轮编译的 `document.json` 读取实际期望页数，不在命令中硬编码十页；十页也不是页数上限或其他报告的推荐页数。
- 静态图表数据可在通用编辑器中编辑；绑定图表事实由报告包字段和公式控制。
- 本地资产仓、工程导入和报告包内嵌资产统一只接受 PNG/JPEG/WebP；SVG、GIF、远程 URL、伪造签名和非法主题 URL 均 fail-closed。

## 5. 发布状态

类型检查、迁移、内核、资产、覆盖测试和 `engine:compile` 可以在不生成 PDF 的情况下执行。完整门禁先生成本轮 `document.json`，再以其 `pages.length` 验收 PDF 页数。最终 `dist/index.html`、财务特化 HTML 与财务参考 PDF 的 byteSize/SHA-256 尚需在完整构建与 PDF 回归后回填；回填前 `release/v1.6.0.json` 保持 `release-candidate`。
