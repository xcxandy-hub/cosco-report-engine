# 修改核心内核提示词

只有所有报告都需要的编辑、渲染、模型、资产、打印或验证能力才应修改 `src/`。一份报告的内容和排版应留在它自己的报告包中。

```text
使用 $cosco-report 修改当前仓库的通用报告内核。

新增或修改的共性能力：
[待填]

使用者操作方式：
- 从哪里进入：[待填]
- 用户的操作：[待填]
- 页面上的反馈：[待填]
- 撤销、刷新保存和导出后的期望：[待填]

适用范围：
- independent 新报告：[适用 / 不适用]
- bound 旧包兼容：[如何保持]
- 横版、竖版或混排：[待填]
- 桌面和 390 px 窄屏：[待填]

不可破坏的边界：
- ReportDocument 版本、迁移和已发布报告包必须兼容；如确需变更结构，同步增加迁移与反例测试。
- independent 图表/表格的数据所有权仍在当前元素，不引入集中数据源或隐式关联。
- 图表/表格常规数据界面保持为按报告包初始结构生成的单元格网格，不退回原始 TSV 文本框；Excel 剪贴板只作为网格的批量录入通道。
- bound 的事实保护、稳定 ID 重放和孤儿告警不得弱化。
- 编辑态与打印态继续使用同一毫米几何和渲染组件。
- 模板能力只能展开为六种原子元素；封面与页眉页脚分别覆盖横版、竖版，并保持一次应用一次撤销、正文保护和逐元素可编辑。
- 不引入 CDN、运行时网络请求、遥测、登录或云上传。
- 不直接修改 dist/index.html 或 artifacts 内生成文件；从源码重建。

实施步骤：
1. 先定位数据模型、交互、持久化、渲染和打印的真实调用链，列出影响范围。
2. 修改最小必要源码，同步更新模型、迁移、文档和测试。
3. 运行 typecheck、migration、engine、assets、overrides、templates、brand-assets、离线检查和构建。
4. 使用财务参考包进行回归，真实检查编辑器、390 px、横竖版和最终 PDF。
5. 报告通过的检查、未执行的压力测试和兼容性风险。

验收标准：
[将功能要求改写为可观察、可复现的用户行为]

涉及数据录入时至少覆盖：逐格修改、表头/系列重命名、增删行列、从当前格粘贴 Excel 连续区域、非法数值逐格提示、取消不写入、一次应用一次撤销、图 A/图 B 隔离、bound 只读、390 px 内部滚动和稳定 ID/组合图配置保留。
```
